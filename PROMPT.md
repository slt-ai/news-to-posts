# Промпт для генерации сайта «Генератор постов по новостям ИИ и технологий»

Скопируй этот текст целиком и передай любой ИИ, чтобы он воссоздал сайт.

```
Задача: создай локальный веб-сервис «Генератор постов по новостям» на Python + Flask.
Пользователь вставляет ссылку на новость или статью на тему ИИ и компьютерных
технологий, сервер скачивает страницу, извлекает текст, отправляет его облачной
языковой модели Ollama Cloud вместе с настройками «голоса» и настроением, модель
пишет оригинальный пост, сервер показывает его и даёт кнопку «Скопировать пост».

=========================================================
ТЕХНОЛОГИИ И ЗАВИСИМОСТИ
=========================================================
- Python 3, Flask, requests, beautifulsoup4, python-dotenv.
- requirements.txt: flask, python-dotenv, requests, beautifulsoup4.
- Все настройки — в файле .env, секреты не попадают в Git.
- Окружение — виртуальное (.venv), запуск: .venv\Scripts\python.exe app.py,
  сайт открывается на http://127.0.0.1:5000.

=========================================================
СТРУКТУРА ПРОЕКТА
=========================================================
site-generation-post/
├── app.py                 — вся логика (Flask + API модели)
├── templates/index.html   — страница с формой и блоком поста
├── static/style.css       — стили
├── static/script.js       — копирование поста и состояние «Готовим…»
├── voice.md               — настройки «голоса» поста (читаются приложением)

├── .env.example           — шаблон .env для Git

=========================================================
BACKEND (app.py)
=========================================================
Подключи библиотеки, загрузи .env через load_dotenv(), создай Flask-приложение.
BASE_DIR — папка проекта, VOICE_FILE = app.py/voice.md.

ЧАСТЬ 1. НАСТРОЙКИ ГОЛОСА (voice.md)
Файл voice.md — это простой текстовый формат «КЛЮЧ: значение» +
комментарии (#). Распознаём ключи (регистр не важен, ключ до «:»):
  ТОН               -> tone
  ДЛИНА             -> length
  КОЛИЧЕСТВО ЭМОДЗИ -> emoji_count
  СТИЛЬ ЗАГОЛОВКА   -> headline_style
Функция load_voice_settings() читает файл (utf-8), пропускает пустые строки
и строки с «#», значения по умолчанию: tone=«дружелюбный», length=«средний»,
emoji_count=3, headline_style=«заглавные». Количество эмодзи превращается
в число в диапазоне 0..5 (не число — оставляем по умолчанию).
Если файла нет — просто возвращаем настройки по умолчанию.

ЧАСТЬ 2. МОДЕЛИ И НАСТРОЕНИЯ
CLOUD_MODELS — список словарей {"id", "name", "price"} (цена за млн токенов,
вход/выход). ВАЖНАЯ ОГОВОРКА: у ряда моделей есть режим «мышления» (thinking),
из-за которого модель тратит лимит токенов на внутренние рассуждения, может
отдать пустой ответ или ВКЛЕИТЬ рассуждения прямо в текст поста (об этом ниже,
«Think-проблема»). Поэтому рабочий порядок (по умолчанию стоит первая):
  - gemma4            «Gemma 4»           $0.14/$0.40  — рекомендуемая, пишет сразу
  - deepseek-v4-flash «DeepSeek V4 Flash» $0.22/$0.66  — тоже пишет сразу
  - gpt-oss:120b      «GPT-OSS 120B»      $0.15/$0.60  — «думает», может не уложиться
  - mistral-large-3   «Mistral Large 3»   $0.50/$1.50
  - kimi-k3           «Kimi K3»           $3.00/$15.00 — топовая, дорогая
  - glm-5.3-flash     «GLM 5.3 Flash»     $0.15/$0.50  — НЕ рекомендуется (мусор в посте)
get_default_model(): берём id из .env (OLLAMA_MODEL), если он есть в списке,
иначе CLOUD_MODELS[0]["id"].

EMOTIONS — словарь настроений: id -> {label, hint}. Метка для интерфейса,
hint — описание, которое модель должна отразить:
  joy        «Радостное 🎉»       — позитивное, лёгкое, с искоркой счастья и улыбкой
  excited    «Восторженное 🤩»    — полное восторга и энергии, будто нашли находку
  inspiring  «Вдохновляющее 🌟»   — мотивирующее, к мечтам, целям, возможностям
  playful    «Игривое 😜»         — с юмором, лёгкой самоиронией и шутками
  mysterious «Интригующее 🔮»     — с интригой и недосказанностью
  business   «Деловое 💼»         — сдержанное, уверенное, по существу

LENGTH_HINTS: короткий -> «2–3 коротких абзаца», средний -> «3–4 абзаца»,
длинный -> «4–6 абзацев».

ЧАСТЬ 3. СКАЧИВАНИЕ СТРАНИЦЫ
Исключения: LinkError («не открылась страница»), ModelError («модель/API»).
fetch_product_page(url): GET с HTTP-заголовками браузера (Chrome UA, Accept,
Accept-Language ru), timeout 15 сек. Коды 403/498 интерпретируем как защиту
от ботов («Сайт запретил автоматическое чтение страницы (код N) — он защищён
от ботов»). HTML разбираем BeautifulSoup: берём <title> (обрезаем до 200),
удаляем script/style/noscript/header/footer/nav/form, текст склеиваем
в одну строку через пробелы, если текста нет — LinkError «На странице не
нашлось текста…». Текст обрезаем до 12000 символов (экономия токенов).
Возвращаем {"title", "text"}.

ЧАСТЬ 4. ЗАПРОС К МОДЕЛИ
build_system_prompt(settings, emotion_id): системный промпт вида
«Ты — креативный технический SMM-копирайтер. Напиши ОДИН оригинальный и
интересный пост для соцсетей по новости или статье на тему ИИ и компьютерных
технологий. Правила: пиши на русском; передай суть новости коротко и понятно
даже тому, кто не в теме; не выдумывай фактов, цифр и деталей, которых нет
в тексте новости; настроение поста: {hint}; общий тон: {tone};
длина: {length_hint}; количество эмодзи: {emoji_count}, не разбрасывать по
каждому абзацу; заголовок ЗАГЛАВНЫМИ словами (либо обычный регистр в
зависимости от headline_style); в конце поста добавь 2–4 подходящих хештега
(#ИИ, #технологии и подобные); разбивай на абзацы с пустыми строками;
верни только текст поста, без пояснений и вступлений».

build_user_prompt(page, extra_note, url): «Вот новость или статья со страницы
{url}: Название страницы: {title} Содержимое страницы: {text} (+ комментарий
от пользователя, если он был). Напиши готовый пост. Только текст».

build_user_prompt_from_note(extra_note, url): если страница не открылась, но
пользователь описал суть новости своими словами: «Ссылка на страницу {url} не
открылась, поэтому суть новости пользователь описал своими словами: {note}.
Напиши готовый пост. Только текст».

build_api_error(response): понятные сообщения по кодам:
  401 — ключ неправильный/неактивный: проверь OLLAMA_API_KEY в .env (без
        пробелов и кавычек), новый ключ на https://ollama.com/settings/keys;
  403 — модель недоступна на твоём тарифе (на Free работают только starter-
        модели), выбери другую модель на странице или пополни кредиты;
  429 — слишком много запросов / закончились кредиты, подожди или проверь
        баланс;
  иначе — «Модель вернула ошибку HTTP {код}».
Добавляй «Ответ сервера: {текст}» из поля error/message тела ответа.

ask_ollama(system_prompt, user_prompt, model):
  - ключ = OLLAMA_API_KEY из .env, если пусто — ModelError с подсказкой
    «В файле .env не заполнен OLLAMA_API_KEY. Создай ключ на
    https://ollama.com/settings/keys и вставь его туда».
  - URL = {OLLAMA_HOST}/api/chat, заголовки Authorization: Bearer {ключ},
    Content-Type: application/json.
  - payload: model; messages = [system, user]; stream: False;
    ОБЯЗАТЕЛЬНО поле "think": False (см. Think-проблему);
    options: temperature 0.9, num_predict 600.
  - timeout 180 сек. Ошибка сети -> ModelError «Запрос к модели не удался»,
    статус != 200 -> ModelError(build_api_error(...)).
  - берём content из data["message"]["content"], strip. Если пусто —
    ModelError «Модель вернула пустой ответ. Попробуй ещё раз».

ЧАСТЬ 5. СТРАНИЦЫ
/ (GET): рендер index.html, post=None, error=None, form=None, page=None,
emotions, models, default_model.
/generate (POST): принимает url, extra, emotion, model из формы.
  url обязателен — иначе ошибка «Пожалуйста, вставь ссылку на новость или статью».
  emotion по умолчанию «joy», если не из EMOTIONS — joy. model из формы,
  если нет в CLOUD_MODELS — дефолт.
  Шаг 1: fetch_product_page; если LinkError — запоминаем причину.
    Если страница не открылась и нет extra: ошибка = причина + «Опиши суть
    новости своими словами в поле „Дополнительно о новости" — тогда пост
    соберётся по твоему описанию».
  Шаг 2: system = build_system_prompt; если страница есть — user =
    build_user_prompt(page, extra, url) (notice=None), иначе user =
    build_user_prompt_from_note(extra, url), notice = «Не удалось открыть
    страницу сайта — пост собран по твоему описанию новости.»
  Шаг 3: ask_ollama(...). ModelError -> страница с error (остальные поля
    формы и notice сохраняются).
  Успех: post = текст модели, error=None, notice сохраняется.
  В форму всегда возвращаем form_data (url, extra, emotion, model), чтобы
  введённое пользователем не стиралось.
Запуск (if __name__ == "__main__"): app.run(host из HOST (по умолч. 127.0.0.1),
port из PORT (по умолч. 5000), debug = (DEBUG == "1")).

=========================================================
THINK-ПРОБЛЕМА (важно, не упусти)
=========================================================
Модели с «мышлением» (gpt-oss, glm и т.п.) при длинном входе уходят в
внутренние рассуждения и тогда: либо возвращают пустой content в поле
message.content, либо (glm-5.3-flash) вклеивают английские рассуждения прямо
в content поста («Let me analyze… Draft:…»). Лечится выбором по умолчанию
модели БЕЗ режима мышления (gemma4) и параметром "think": False в запросе.
Именно поэтому gemma4 стоит первой в списке, а glm-5.3-flash помечена как
нежелательная.

ФРОНТЕНД (index.html + style.css + script.js)
=========================================================
Одна страница, lang="ru", UTF-8. Сверху шапка: заголовок «Генератор постов
по новостям ✍️» и подпись «Вставь ссылку на новость или статью — нейросеть
изучит текст и напишет живой пост». Появляющиеся карточки: error-box («⚠️ …»)
и notice-box («ℹ️ …»). Затем форма (POST /generate):
  - «Ссылка на новость/статью *» — input type=url, обязательное, плейсхолдер
    https://example.com/article/123, value подставляется из формы;
  - «Дополнительно о новости (необязательно)» — textarea rows=3, плейсхолдер
    «Суть новости своими словами, важные акценты, своё мнение — модель учтёт
    это в посте»;
  - «Настроение поста» — радиокнопки-«чипы» (эмодзи-настроения из EMOTIONS,
    скрытые радио input + label .mood-chip, выбранное подсвечивается;
    первый варианта выбран по умолчанию, сохранённое из формы — тоже);
  - «Модель» — select из CLOUD_MODELS, показываем «Имя · $цена/млн токенов»,
    выбран дефолт (или сохранённое из формы); подсказка про цены и ссылку
    https://ollama.com/pricing;
  - кнопка «Сформировать пост».
Блок «Готовый пост»: если post есть — строка-мета «📄 Страница: {title}»
(только если страница реально открывалась), текст поста в .post-box
(безопасный рендер — Jinja autoescape, перенос строк через white-space:
pre-wrap), кнопка «Скопировать пост», скрытое сообщение «Пост скопирован ✅».
Если поста нет — плейсхолдер «... Здесь появится готовый пост по этой новости ...».

script.js:
  - при submit формы кнопка меняется на «Готовим пост для тебя… ✍️» и
    блокируется (.loading) — чтобы пользователь видел, что идёт работа;
  - кнопка копирования: берёт innerText из .post-box, копирует через
    navigator.clipboard.writeText, при неудаче fallback через скрытый
    textarea + execCommand("copy"); показывает «Пост скопирован ✅» на 2 сек.

style.css:
  - фиолетовый градиентный фон (#667eea -> #764ba2), белые карточки с
    тенью, скругление 14px, максимум 720px по центру;
  - форма: поля с рамкой, radius 10px, синий акцент #667eea при фокусе,
    рамка 2px #e3e3e3; чипы-настроения — «пилюли» (border-radius 999px,
    выбранное — border акцент + фон #eef1ff);
  - error-box: левая рамка 6px #e0245e, розовый текст; notice-box: рамка
    акцентом, синий текст;
  - кнопки: btn-primary — синяя на всю ширину, hover-тень, состояние loading
    (opacity 0.6, cursor progress); btn-secondary — прозрачная с рамкой;
  - .post-box: светло-лиловый фон #f7f8ff, рамка #e3e8ff, pre-wrap;
  - .copy-msg скрыт, показывается классом .visible (зелёный #22a45d).

voice.md:
  Формат «КЛЮЧ: значение» + комментарии #. Обязательны строки:
    ТОН ПОСТА: дружелюбный
    ДЛИНА ПОСТА: средний
    КОЛИЧЕСТВО ЭМОДЗИ: 3
    СТИЛЬ ЗАГОЛОВКА: заглавные буквы
  Ниже — блок самодокументации (комментарии #: варианты тонов, длины,
  диапазон эмодзи 0–5, стили заголовка с примером «ЭТА НОВОСТЬ МЕНЯЕТ ВСЁ!»,
  где менять правила модели).

.env и .env.example:
  HOST=127.0.0.1
  PORT=5000
  DEBUG=1
  OLLAMA_API_KEY=          (пусто; пользователь вписывает ключ сам)
  OLLAMA_HOST=https://ollama.com
  OLLAMA_MODEL=gemma4      (с комментарием: рекомендуемая, пишет сразу;
                             gpt-oss/glm могут выдать пустой/ломаный пост)
  .env.example — тот же шаблон без секретов, для Git.

=========================================================
ВАЖНЫЕ ФАКТЫ О ВНЕШНЕМ API (для работоспособности)
=========================================================
- Ключ: https://ollama.com/settings/keys (именно API-ключ, не SSH). Ключ
  кладётся в OLLAMA_API_KEY.
- Аутентификация: заголовок Authorization: Bearer <ключ>.
- /api/chat: POST, тело JSON {model, messages:[{role,content}], stream,
  think, options}, модель указывается БЕЗ суффикса -cloud (gemma4,
  gpt-oss:120b и т.д.).
- Цены: https://ollama.com/pricing.
- Многие новостные/магазинные сайты (Wildberries 498, часть СМИ 403)
  блокируют скриптовые GET-запросы — это НЕ баг, для этого есть fallback
  на описание пользователем сути новости своими словами.
```
